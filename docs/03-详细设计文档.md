## 2. 接口通用约定

- **基址**：`http://localhost:8095`；成功 200 + JSON body（直接是数据，无包裹层）。
- **失败**：`{ "error": "中文说明" }` + HTTP 状态码：400 参数/规则拒绝、401 未登录/失效、403 越权、404 不存在、409 状态冲突、500 内部错误（server.js:155-161, 878-884）。
- **鉴权**：`Authorization: Bearer <token>`；也接受 `?token=`（单证新标签页场景，server.js:857）。公开端点：`/api/health`、`/api/plans`、`/api/login`、静态页。
- **请求体**：POST/PUT JSON，上限 **8MB**，超限断流 400；非法 JSON 400（server.js:814-830）。
- **路由机制**：`route(method, pattern, handler, opts)` 注册表，`:param` 编译为正则捕获组，decodeURIComponent 后传入（server.js:343-351, 858-876）。
- **部分更新**：PUT 类接口只校验/覆盖 body 中出现的字段（partial 模式）。

## 4. 订单状态机

```
                 confirm（扣库存+计应收）        ship（记物流）
   ┌───────┐ ─────────────────────► ┌───────────┐ ──────────► ┌─────────┐
   │ quote │                        │ confirmed │             │ shipped │终态
   └───┬───┘ ◄── 1688未付款导入      └─────┬─────┘             └─────────┘
       │ cancel                            │ cancel（回补库存）
       ▼                                   ▼
   ┌───────────┐                      ┌───────────┐
   │ cancelled │终态                   │ cancelled │终态
   └───────────┘                      └───────────┘
```

TRANSITIONS（server.js:303-308）：

| 当前态 | 允许目标 | 副作用 |
|---|---|---|
| quote | confirmed | confirmedAt=now；deductOrderStock（逐项 out 流水） |
| quote | cancelled | 无库存动作 |
| confirmed | shipped | shippedAt=now；写入 shipping（可选） |
| confirmed | cancelled | restoreOrderStock（逐项 in 流水，reason=取消回补） |
| shipped / cancelled | （无） | 任何跳转 409 |

收款与状态：quote 拒收（409）；confirmed/shipped 可多次收款直至结清；取消不回滚已收款记录（业务上取消前应先协商退款，系统留痕不抹账）。

## 5. 核心算法设计

### 5.1 应收与账龄（server.js:186-217）

```
对每个订单 o：
  若 o.status ∉ {confirmed, shipped} → 跳过
  due = round2(o.total − o.paid)；due ≤ 0 → 跳过
  days = floor((now − (o.confirmedAt || o.createdAt)) / 86400000)
  bucket = days > 60 ? d60p : days > 30 ? d31_60 : d0_30
  按 o.currency 累加 total 与 bucket（CNY/USD 独立，绝不混加）
  按 customerId×currency 聚合客户条目，附逐单 {no, due, days, bucket}
客户条目按 total 倒序
```

输出：`{byCurrency:{CNY:{total,buckets},USD:{total,buckets}}, customers:[{customerId,name,type,contact,phone,currency,total,orders[]}]}`。
边界：账龄按自然日向下取整；恰好 30 天入 0-30 桶、31 天入 31-60 桶、61 天入 60+ 桶。

### 5.2 库存流水（server.js:219-238）

唯一变动入口 `adjustStock(product, delta, type, reason, user, refOrderId)`：
`before=stock → stock+=delta → push 流水{before, after, …}`。

| 触发 | type | delta | reason |
|---|---|---|---|
| 采购入库 | in | +qty | note 或「采购入库」 |
| 盘点 | adjust | 实盘−账面（0 不记） | note 或「盘点调整」 |
| 订单确认 | out | −item.qty | 「订单 YW-xxxx 确认」 |
| 取消已确认订单 | in | +item.qty | 「订单 YW-xxxx 取消回补」 |
| 期初库存（种子） | in | +初始量 | 「期初库存」，userName=系统 |

允许负库存（缺货现实）；商品被删除后订单联动找不到商品则跳过（`if (p)` 守卫）。

### 5.3 拍照识货 dHash（app.js:268-287 + server.js:480-494）

**前端指纹计算**（原图不出浏览器）：
1. `createImageBitmap(file)` → canvas 缩放至 **9×8**；
2. 每像素灰度 `g = 0.299R + 0.587G + 0.114B`；
3. 每行相邻比较 `g[x] > g[x+1] → 1`，8 行×8 比较 = **64 位**；
4. 每 4 位转 1 位 hex → **16 位小写 hex** 指纹。

**服务端比对**：
1. 校验 `^[0-9a-f]{16}$`；
2. `BigInt('0x'+hash)` 异或，逐位 `&1n` 计数得**汉氏距离**；
3. 仅比对有 photoHash 的商品；按距离升序取 **Top8**；`match = distance ≤ 10`。

**前端分级**：≤6 很可能同款（绿）/ ≤10 相似（橙）/ >10 仅供参考（灰）。
特性：对缩放/轻微亮度变化鲁棒；对旋转/裁剪/语义相似不鲁棒（ADR-1 已声明局限）。

### 5.4 1688 导入管线

**前端**（app.js:811-913）：
1. 读文件 ArrayBuffer → `TextDecoder('utf-8',{fatal:true})`，抛错则回退 `TextDecoder('gbk')`；
2. `parseCSV`：字符状态机，支持双引号包裹、`""` 转义、CRLF、去 BOM、过滤全空行；
3. `mapImportRows`：表头**模糊包含匹配**（订单编号/订单号、买家、货品名称/商品名称、货号、数量、单价、订单状态/状态、收货人、电话/手机）；缺必需列（订单编号/货品名称/数量/单价）报错；买家名缺省回退收货人；
4. 预览模态（行数/合并订单数/前 8 行）→ 用户确认 → POST rows。

**服务端**（server.js:579-644）：
1. 校验 ≤500 行；逐行校验 externalNo(≤40)/buyerName(≤60)/productName(≤60)/qty 正整数/price>0；
2. **去重**：externalNo 已存在于 orders → 整行跳过（计入 skipped）；
3. 按 externalNo 分组（同单多行合并）；
4. 客户：按 name 精确匹配复用，否则新建（wholesale，note=「1688 导入」，contact/phone 取收货人）；
5. 商品：先按 sku、再按 name 匹配复用；否则新建（unit=件，priceCny=行价，**priceUsd=round2(价/7)**，stock=0，sku 缺省 `IMP-序号`，冲突加 `-seq` 后缀）；
6. 同商品多行 qty 累加合并为一个 item；
7. 状态映射：`/等待买家付款|未付款/.test(status)` → quote；否则 confirmed + **自动全额收款**（method=1688，note=平台已付款）；
8. buildOrder 落单（confirmed 扣库存——导入商品 stock=0 会记负库存，符合缺货现实）；一次 persist。

**幂等性**：重复提交同一批 rows → imported=0、skipped=全部行数，无副作用。

### 5.5 单证渲染（server.js:717-807）

**鉴权**：`docAuth(url)` 从 `?token=` 取会话，失效 401「登录已失效，请重新登录后打开单证」。

**商业发票**（/docs/invoice/:id）：
- 抬头：settings.companyName/address/phone；发票号=o.no；日期=confirmedAt||createdAt（ISO 日期）；贸易条款=settings.tradeTerms；
- 买方：客户档案 name/contact/phone（档案已删则回退订单快照名）；目的地=shipping.destination；
- 明细行：序号/名称+SKU/数量/单位/单价/金额（订单快照价，两位小数）；合计=o.total；
- 银行信息：settings 四字段；已收=o.paid、未收=round2(total−paid)；备注=shipping.note；签字栏。

**装箱单**（/docs/packing/:id）逐行计算：

```
spec = 商品当前箱规（注意：用当前档案，非订单快照）
若 spec 缺失或 pcsPerCarton=0 → 该行全「—」，missing=true
cartons = ceil(qty / pcsPerCarton)
cbm = round2(cartonL × cartonW × cartonH / 1e6 × cartons)   // cm³→m³
gw  = round2(grossWeightKg × cartons)
nw  = round2(netWeightKg × cartons)
合计行累加；missing=true 时页首中英双语警告
```

- 日期=shippedAt||confirmedAt||createdAt；唛头=`客户名 / 单号 / 目的地`；货代=shipping.forwarder。
- 输出：docPage 模板（A4 版式、表格边框、`@media print` 隐藏工具栏），页首「打印 / 另存为 PDF」按钮 `window.print()`。
- 所有动态字段经 esc() 转义。

- 样式：style.css 移动端优先，琥珀主题（--orange #d97706 系），桌面主区居中 760px。

### 8.2 状态与数据流

| 全局变量 | 用途 |
|---|---|
| token | localStorage `yw_token` 持久化；401 即清除回登录页 |
| S / me | /api/state 全量快照 / 当前用户 |

### 8.4 安全与兼容

- 所有插值经 esc()（名称/备注/搜索词等用户可控字符串）；ID 为服务端 UUID 直接拼 onclick 无注入面。
- 剪贴板 API 不可用时降级 execCommand。
- TextDecoder GBK 回退覆盖 1688 导出常见编码；BOM 剥离。
- 401 统一拦截（login 除外）→ 清 token → 登录页，避免静默失败。

## 9. 持久化与并发

- **写路径**：每个写端点末尾 `persist(state)`——`writeFileSync(tmp)` + `renameSync`（server.js:132-137）。rename 原子性保证崩溃时主文件要么是旧全量要么是新全量。
- **并发**：Node 单线程，handler 内状态变更同步执行（readBody 的 await 在变更之前），请求间天然串行，无竞态、无锁。
- **读路径**：/api/state 每次实时计算应收；照片读文件带 no-cache。
- **已知局限**：persist 为同步全量写，数据量极大时阻塞事件循环（演进：数据层外置）；会话内存态重启丢失。

## 10. 异常处理

| 层 | 行为 |
|---|---|
| 业务拒绝 | throw HttpError(code, 中文消息) → 统一 `{error}` JSON |
| 未知异常 | console.error + 500「服务器内部错误」（不泄漏堆栈） |
| 请求体 | >8MB 断流 400；非法 JSON 400 |
| 路由未命中 | 404「接口不存在」 |
| 前端 | api() 非 2xx throw Error(data.error) → toast 红色展示；401 特殊处理回登录页 |
