## 1. 背景与产品目标

### 1.1 业务背景

义乌国际商贸城档口小老板的典型经营状态：

- **内贸批发 + 小额外贸混做**：同一档口既做国内批发（人民币、微信/支付宝收款、月结赊账），又接中东/拉美/非洲小单（美元报价、T/T 收款、要发票和装箱单）。
- **接单靠微信 / WhatsApp**：报价靠手打文字或拍脑袋，没有正式报价单。
- **记账靠 Excel + 脑子**：谁欠多少钱、欠了多久，月底才对一次账，催款全凭记忆。
- **SKU 极多**：几百上千种小商品，客户拿着照片问「这个有没有」，翻货架找货耗时。
- **人手少**：老板 + 1~3 个店员，店员不能乱动库存和账。
- **预算敏感**：年费几百元可接受，上万元的外贸 SaaS 用不起。

### 1.2 市场缝隙（调研结论）

| 需求 | 秦丝类进销存 | OKKI 类外贸 SaaS | Chinagoods 官方平台 |
|---|---|---|---|
| 手机快速开单 | ✅ | 部分 | ❌ |
| 应收账龄 + 催款 | 弱 | ✅ | ❌ |
| 美元报价 + 装箱单/发票 | ❌ | ✅ | 部分 |
| 1688 订单归拢 | 弱 | ❌ | ❌ |
| 档口可承受的价格 | ✅（免费~800/年） | ❌（19800/年起） | 会员费 |

**「内贸 + 小额外贸混做、几百元级定价、应收催款为核心」的组合没有现成产品完整覆盖**——这是本产品的切入点。

### 1.3 产品目标

| 目标 | 衡量方式 |
|---|---|
| 替代「微信 + Excel」 | 开单、收款、催款三个核心动作均在 3 步内完成 |
| 应收一目了然 | 打开「应收」页即见分币种总额、账龄分层、按客户欠款明细 |
| 内贸外贸一本账 | 同一系统内 CNY/USD 双币开单、双币应收分开汇总不混加 |
| 单证不求人 | 外贸订单发货后一键生成中英双语商业发票 / 装箱单 |
| 零门槛运行 | 一条命令启动，无 npm 安装、无数据库、无外部服务 |

### 1.4 设计原则（需求级约束）

1. **做轻做快**：移动端优先，核心链路三步内完成。
2. **可靠性放服务端**：金额口径、状态流转、权限、库存一致性全部服务端校验兜底，前端只管展示；绕过前端直接调 API 也不能破坏规则。
3. **零依赖**：仅 Node.js 内置模块 + 原生浏览器能力，离线可运行（识货、导入、单证均不依赖外部 API）。

## 2. 用户与角色

| 角色 | 画像 | 核心诉求 | 权限边界 |
|---|---|---|---|
| **老板（boss）** | 档口经营者，自己接单也管账 | 随时开单、看清谁欠钱、管员工管库存 | 全部权限 |
| **店员（clerk）** | 档口帮工，接待客户、打包发货 | 快速开单报价、登记收款、查货找货 | 不能删除数据、不能动库存、不能管员工/设置 |

- 演示账号：`boss / boss123`、`clerk / clerk123`（首次启动自动注入）。
- 老板可增删员工、重置密码、调整角色；不能删除自己、不能降级自己（防锁死）。
- 客户（买家）**不是系统用户**：客户是档案数据，不登录系统；报价单/催款单以文本复制方式经微信/WhatsApp 发给客户。

### 2.1 典型使用场景

| # | 场景 | 链路 |
|---|---|---|
| S1 | 国内批发客户微信要货 | 开单选客户（自动 ¥）→ 搜商品加购 → 改价（讲价）→ 存报价单 → 复制中文报价单发微信 → 客户同意后确认订单（扣库存、计应收）→ 发货 → 分期收款 |
| S2 | 迪拜客户 WhatsApp 询价 | 开单选外贸客户（自动 $）→ 加购 → 存报价 → 复制英文 QUOTATION 发 WhatsApp → 确认 → 发货登记货代/目的地 → 生成商业发票 + 装箱单（浏览器另存 PDF 发客户）→ T/T 收款 |
| S3 | 月底催款 | 应收页看 60+ 天高危 → 按客户复制催款单（中/英）→ 微信/WhatsApp 发送 → 收到钱点「收款」登记 |
| S4 | 客户拿照片问货 | 开单页点「📷 识货」→ 拍照/选图 → 系统按相似度列出商品 → 一键加入订单 |
| S5 | 1688 网店订单归拢 | 卖家后台导出 CSV → 更多页导入（自动识别 GBK）→ 预览确认 → 自动建客户/商品/订单，已付款自动记收款 → 与档口订单一起对账 |
| S6 | 工厂补货 / 月度盘点 | 货品页「入库」登记采购量；「盘点」输入实盘数，系统自动记差异流水 |
| S7 | 店员离职 | 老板删除员工账号，其全部会话立即失效 |

## 3. 功能需求

优先级：P0 = 核心链路（开单版套餐边界）；P1 = 进销存版增量；P2 = 外贸全能版增量。
每条需求附验收标准（AC），编号与 §7 验证映射对应。

### FR-01 登录与会话（P0）

- 用户名 + 密码登录；密码加盐哈希存储，任何接口响应不携带哈希/盐。
- 登录成功发放会话令牌，有效期 7 天；注销即失效。
- 未登录/令牌过期访问受保护接口返回 401，前端自动回到登录页。
- **AC**：错误密码 401；未登录访问 401；响应不含 hash 字段；重置他人密码后其旧会话失效。

### FR-02 手机开单与报价（P0）

- 选客户自动带出币种：批发客户 → CNY，外贸客户 → USD；可手动切换，切换后购物车单价按对应币种价格重置。
- 商品按名称/货号搜索；点「＋」加购，数量步进或直接输入；**支持手动改价**（档口讲价场景），改价必须 > 0。
- 两种保存方式：**存为报价单**（不扣库存、不计应收、不能收款）/ **直接确认订单**（扣库存、计应收）。
- 订单号系统自动生成 `YW-0001` 递增，不可指定。
- 单笔订单 1~100 种商品；数量为正整数；金额两位小数。
- 数量超过当前库存时前端提示「确认后库存将记为负数（缺货）」，**不阻塞成交**。
- **AC**：报价单金额 = Σ数量×单价；报价不扣库存；负改价 400；缺客户/缺商品拒绝保存。

### FR-03 订单生命周期与发货（P0）

- 状态机：`报价 quote → 已确认 confirmed → 已发货 shipped`；quote/confirmed 可取消 `cancelled`；shipped/cancelled 为终态。
- 确认订单：自动扣减库存（记流水）、开始计应收。
- 取消已确认订单：自动回补库存（记流水）；取消报价单无库存动作。
- 发货登记：货代/物流公司、目的地、备注（均选填，≤120 字）。
- 订单列表按状态筛选（全部/报价/已确认/已发货/已取消），按创建时间倒序。
- 订单卡片展示：客户、金额、已收/未收、收款记录折叠明细、物流信息、1688 来源标记。
- **AC**：非法状态跳转 409（如已发货再取消）；确认扣库存、取消回补数额精确；发货信息落库。

### FR-04 收款登记（P0）

- 仅 confirmed/shipped 订单可收款；报价单收款拒绝（409）。
- 支持多笔分期收款；每笔记录金额、方式（微信/支付宝/现金/银行转账/T/T/1688/其他）、备注、时间。
- **禁止超收**：单笔金额 > 0 且 ≤ 未收余额；`paid` 由服务端累加，客户端不可直接改。
- 结清后订单显示「已结清」，不再出现在应收。
- **AC**：超收 400；部分收款后 paid 精确累加；应收即时减少。

### FR-05 应收对账与催款（P0，产品核心差异化）

- **分币种汇总**：CNY 与 USD 各自总额，绝不混加。
- **账龄分层**：0-30 天 / 31-60 天 / 60 天以上（高危标红）；账龄自订单确认日起算。
- 仅 confirmed/shipped 且未结清订单计入应收。
- 按客户 × 币种汇总欠款，逐单列示拖款天数，客户按欠款总额倒序。
- **催款单一键复制**：中文（发微信）/ 英文（发 WhatsApp），含逐单欠款与天数、合计、公司抬头。
- 应收页每单提供快捷「收款」入口。
- 全部口径服务端计算，前端只展示。
- **AC**：种子数据 USD 合计 2254（60+ 天 1534、31-60 天 720）、CNY 合计 2820（0-30 天）；报价单/已取消/已结清不计入；收款后即时更新。

### FR-06 商品档案与照片（P1）

- 商品字段：名称（≤60 字）、货号（≤30 字，**全局唯一**）、单位（≤8 字）、批发价 ¥、外贸价 $（均 > 0）、HS 编码（选填）、外贸箱规（选填）、照片。
- 期初库存仅创建时指定；此后**禁止直接编辑库存**（必须走入库/盘点，见 FR-07）。
- 照片上传：JPG/PNG/WebP，≤3MB，服务端魔数校验拒伪造；上传时同步计算感知哈希用于识货。
- 商品搜索、「只看缺货/偏低」筛选（阈值可配，默认 100）。
- 删除商品仅老板；历史订单不受影响（订单存快照）。
- **AC**：重复货号 400；PUT 改 stock 400；伪造图片 400；店员删除 403。

### FR-07 精确库存（P1）

- **一切库存变动必须经流水**：采购入库（in）、盘点调整（adjust）、订单确认扣减（out）、取消回补（in）。
- 每笔流水记录：类型、增减量、**变动前/后值**、原因、关联订单、操作人、时间——可完整审计。
- 盘点：输入实盘数，系统计算差异并记 adjust 流水；账实一致时提示无需调整。
- **允许负库存**：档口缺货也先接单的现实；负数标红「缺货」，≤阈值标橙「偏低」。
- 库存流水查询（最近 200 条，倒序）。
- 入库/盘点仅老板可操作。
- **AC**：入库 +30 精确到账；盘点差异 = 实盘 − 账面；店员动库存 403；流水含 before/after。

### FR-08 拍照识货（P1）

- 开单页「📷 识货」：拍照或从相册选图 → 浏览器本地计算感知哈希（不上传原图）→ 服务端与商品照片指纹比对 → 按相似度排序列出 Top8。
- 相似度分级：汉氏距离 ≤6「很可能同款」（绿）、≤10「相似」（橙）、其余「仅供参考」（灰）。
- 结果一键「加入订单」。
- 无任何商品照片时给出引导（先去货品页上传照片）。
- 零外部 AI 依赖、离线可用、无 API 费用。
- **AC**：相同指纹 distance=0 且 match=true；远指纹不判同款；非法指纹 400。

### FR-09 外贸单证（P2）

- **商业发票 COMMERCIAL INVOICE**：中英双语，含卖方抬头/地址/电话、发票号（=订单号）、日期、贸易条款、买方信息、目的地、逐行货品（名称/SKU/数量/单位/单价/金额）、合计、收款银行信息（户名/银行/账号/SWIFT）、已收/未收、备注、签字栏。
- **装箱单 PACKING LIST**：中英双语，逐行计算 **箱数 = ⌈数量/每箱装量⌉、体积 CBM = 长×宽×高(cm)/10⁶×箱数、毛/净重 = 单箱重×箱数**，含合计行、唛头（客户名/单号/目的地）、货代。
- 缺箱规的商品行显示「—」并在页首给出中英双语警告，不阻塞出单。
- 输出为打印页（HTML + 打印 CSS），浏览器「打印 / 另存为 PDF」即得正式单证；不引 PDF 库。
- 单证页经 `?token=` 鉴权（新标签页场景），无 token 401。
- 公司抬头/银行信息/贸易条款在「公司设置」维护（FR-13）。
- **AC**：发票含正确合计；装箱单含箱数/CBM；无 token 401；缺箱规出警告。

### FR-10 1688 订单导入（P1）

- 输入方式：CSV 文件（1688 卖家后台导出）或直接粘贴文本；提供样例 CSV 下载。
- **编码自动识别**：UTF-8（含 BOM）优先，解码失败自动回退 GBK。
- **列名模糊映射**：订单编号/订单号、买家、货品名称/商品名称、货号、数量、单价、订单状态/状态、收货人、电话/手机；缺必需列（订单编号/货品名称/数量/单价）明确报错。
- 导入前预览：行数、合并后订单数、前 8 行明细，确认后才写入。
- **同单多行合并为一笔订单**；同商品多行数量累加。
- **订单号去重（幂等）**：已存在的 externalNo 整单跳过，重复导入不产生重复数据。
- 自动创建缺失客户（按买家名匹配，批发类型）与商品（先按货号、再按名称匹配；新建商品外贸价 = 人民币价/7，库存 0）。
- 状态映射：含「等待买家付款/未付款」→ 报价单；其余 → 已确认订单并**自动登记全额收款**（方式=1688，备注=平台已付款）。
- 单次 ≤500 行；导入结果汇总（导入 N 单/跳过 N 行/新建客户/商品数）。
- **AC**：3 行样例导入 2 单；同单合并金额精确；已付款自动记收款；未付款转报价；重复导入全部跳过；商品只建一次。

### FR-11 客户管理（P0）

- 客户字段：名称（≤60 字）、类型（批发 wholesale / 外贸 foreign）、联系人、电话/WhatsApp、备注（各 ≤120 字）。
- 客户列表直显欠款（分币种）；改名同步历史订单显示名。
- **有订单的客户禁删**（409）；无订单客户可删（仅老板）。
- **AC**：有订单客户删除 409；临时客户可删；改名后订单显示名同步。

### FR-12 多用户与权限（P1）

- 老板/店员两角色，权限矩阵见 [03-详细设计 §6](03-详细设计文档.md)。
- 老板：新增员工（用户名 3-20 位字母/数字/下划线、密码 ≥6 位）、重置密码、升降角色、删除员工。
- 保护规则：不能删除自己、不能降级自己；重置他人密码即踢掉其全部会话；删除员工即失效其全部会话。
- 店员端 UI 隐藏无权操作按钮，且服务端 403 兜底（双层防线）。
- **AC**：店员建员工/改设置/动库存/删数据均 403；新员工可登录；旧密码重置后失效；不能删自己。

### FR-13 公司设置（P2）

- 单证抬头：公司名称、地址、电话、贸易条款（默认 FOB Ningbo）、开户银行、银行账号、SWIFT。
- 系统参数：缺货预警阈值（非负整数，默认 100）。
- 仅老板可改；设置即时作用于其后生成的单证与报价/催款文本。
- **AC**：店员改设置 403；老板修改后读回一致。

### FR-14 SaaS 定价页（P0，商业化展示）

- 公开页 `/pricing.html`（无需登录），三档套餐**按功能模块定价**：

| 套餐 | 月付 | 年付 | 功能边界 | 账号数 |
|---|---|---|---|---|
| 开单版 | ¥29 | ¥290 | 开单报价 + 客户 + 应收催款 | 1 |
| 进销存版 ⭐ | ¥59 | ¥590 | + 照片档案 + 精确库存 + 识货 + 1688 导入 | 3 |
| 外贸全能版 | ¥99 | ¥990 | + 发票/装箱单 + 箱规计算 + 公司抬头自定义 | 10 |

- 月付/年付切换（年付 = 付 10 个月用 12 个月）；功能对比表。
- 定价为目标价，正式商用前结合商户访谈调整；**当前演示系统全功能免费体验，定价页不含真实支付**。
- **AC**：公开接口返回 3 套餐；定价页可访问；年付切换数字正确（290/590/990）。

## 4. 非功能需求

| # | 类别 | 需求 | 落地方式 |
|---|---|---|---|
| NFR-01 | 零依赖 | 无 npm 安装、无外部中间件、无外部 API 也可全功能运行 | 仅 node:http/fs/path/crypto + 原生浏览器能力 |
| NFR-02 | 可直接运行 | 一条命令启动；本机 PATH 无 node 也能起 | `./start.sh` 自动探测常见 Node 安装位置 |
| NFR-03 | 数据保护 | 重启不丢数据；进程崩溃不损坏数据文件；数据目录 git 忽略 | JSON 原子写（tmp→rename）；`data/` 不入库 |
| NFR-04 | 安全 | 密码不可逆存储；防 XSS/路径穿越/伪造图片/超大请求 | scrypt 加盐；全量 HTML 转义；文件名白名单；魔数校验；8MB 请求体上限 |

## 5. 约束与假设

1. 单店单进程部署（档口一台电脑/手机浏览器访问），不做多租户隔离——每个商户独立部署一套。
2. 汇率不做实时换算：CNY/USD 双价独立维护，应收分币种不混加；导入商品的外贸价按 /7 估算仅供起步。
3. 客户不登录系统；对外交付物是「复制的文本 + 打印的单证」，不做客户自助门户。
4. 1688 无开放平台企业凭证，导入走卖家后台 CSV 导出这一现成通路。
5. 演示种子数据（8 商品/4 客户/4 订单）首次启动注入；**data/ 目录的删除/重置必须先经用户确认**。
