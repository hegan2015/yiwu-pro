## 1. 架构目标与硬约束

| 约束 | 来源 | 架构响应 |
|---|---|---|
| 零外部依赖 | 用户交付标准 | 仅 Node.js 内置模块（http/fs/path/crypto），无 npm、无数据库、无消息队列、无外部 API |
| 一条命令可运行 | 用户交付标准 | 单进程单文件后端 + 静态前端同进程托管；`start.sh` 自动探测 Node 运行时 |
| 可靠性放服务端 | 既有工程原则 | 金额/状态机/权限/库存一致性全部在 server.js 校验，前端仅展示与提示 |
| 数据保护 | 既有工程原则 | JSON 原子持久化；`data/` git 忽略；停服务不触碰数据 |
| 移动端优先 | 需求 NFR-05 | 无构建原生 SPA，底部五页签，桌面居中 760px |
| 四系统端口共存 | 工作区现状 | 8095，与 ride(8090)/payment(8080/8443)/cs(8096) 完全错开 |

## 2. 形态选型

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **单进程 Node.js + JSON 文件库**（选定） | 零依赖、启动秒级、部署一个目录、内置 crypto/http 足够 | 单机单写者、无 SQL 查询能力 | ✅ 档口规模（千级 SKU/万级订单）完全够用 |
| Spring Boot + H2（同工作区 ride/payment/cs 风格） | 与其余系统同栈 | 需 JDK + Maven 构建链，违背「零依赖一条命令」 | ❌ 本系统定位更轻 |
| Node + SQLite | SQL 能力 | 需第三方原生模块（better-sqlite3），破坏零依赖 | ❌ 列为演进项 |
| 多进程微服务 | 扩展性 | 档口场景无跨域事务需求，运维成本不成比例 | ❌ |

**决策**：单进程单体 + 进程内模块化。规模化的演进路径是「数据层外置（SQLite/PG）→ 会话持久化 → 反向代理多进程」，业务规则层不需要重写。

## 3. 逻辑架构

```
 手机/桌面浏览器（原生 SPA，无框架无构建）
 ┌──────────────────────────────────────────┐
 │ index.html + app.js + style.css           │
 │  · 五页签：开单/订单/应收/货品/更多         │
 │  · 浏览器端计算：canvas dHash 感知哈希      │
 │  · CSV 解析（UTF-8/GBK 自动识别）+ 预览     │
 │  · 剪贴板复制（报价单/催款单，中英文）      │
 │ pricing.html（公开定价页，fetch /api/plans）│
 └───────────────┬──────────────────────────┘
                 │ HTTP/JSON · Authorization: Bearer <token>
                 │ 单证新标签页：?token=
 ┌───────────────▼──────────────────────────┐
 │ server.js 单进程（node:http，:8095）       │
 │ ┌──────────────────────────────────────┐ │
 │ │ 接入层：静态白名单托管 / 照片托管       │ │
 │ │ 路由注册表 + 会话鉴权 + 8MB 请求体限制  │ │
 │ ├──────────────────────────────────────┤ │
 │ │ 业务层（全部服务端兜底）：              │ │
 │ │  订单状态机 TRANSITIONS + 库存联动      │ │
 │ │  收款校验（禁超收）· 应收口径统一计算   │ │
 │ │  库存流水 adjustStock（唯一变动入口）   │ │
 │ │  权限 requireBoss · 字段校验器          │ │
 │ │  1688 导入（去重/合并/自动建档）        │ │
 │ │  识货比对（BigInt 汉氏距离）            │ │
 │ │  单证渲染（发票/装箱单 HTML+打印CSS）   │ │
 │ ├──────────────────────────────────────┤ │
 │ │ 状态层：内存 state（load 时字段迁移）   │ │
 │ │ 会话 Map（内存，7 天 TTL）              │ │
 │ ├──────────────────────────────────────┤ │
 │ │ 持久层：persist() 原子写 tmp→rename     │ │
 │ └──────────────────────────────────────┘ │
 └───────────────┬──────────────────────────┘
                 │
   data/store.json（全量业务数据，单文件）
   data/photos/<productId>.<jpg|png|webp>（商品照片）
```

**关键特征**：

- **无外部集成**：不调任何第三方服务。识货的「AI」是浏览器 canvas + 服务端位运算；导入的「对接」是 CSV 文件；单证的「PDF」是浏览器打印。全部离线可用。
- **全量状态模式**：前端每次变更后 `GET /api/state` 拉全量（me/商品/客户/订单/应收/设置/员工），无增量同步、无本地缓存一致性问题——档口数据量下这是最简单可靠的方案。
- **应收不落库**：`computeReceivables()` 每次请求实时计算（server.js:186），无快照表、无调度器，天然与订单/收款状态一致。

## 5. 数据架构

| 数据 | 载体 | 一致性策略 |
|---|---|---|
| 业务全量（users/settings/products/customers/orders/stockLedger/seq） | `data/store.json` 单文件 | 每次写操作后 persist()：先写 `.tmp` 再 `rename`（POSIX 原子），崩溃不损坏主文件 |
| 商品照片 | `data/photos/<productId>.<ext>` | 上传即覆盖同名旧扩展名文件；store.json 存相对路径 |
| 会话 | 进程内存 Map | 重启即失效（需重登）——已知局限，演进项 |
| 应收/账龄 | **不存储**，请求时实时计算 | 与订单/收款永远一致，无同步问题 |
| 库存当前值 | products[].stock | 只能经 adjustStock 变动，每笔流水含 before/after，可重放审计 |

**向前兼容迁移**：load()（server.js:106-130）对旧版本数据补齐新增字段（photo/photoHash/cartonSpec/hsCode/source/externalNo/shipping），缺 users 时重建演示账号，settings 与默认值合并——升级不丢数据、不需手工迁移脚本。

**并发模型**：Node 单线程事件循环，请求处理同步完成（无 await 穿插于状态变更），天然串行化，无需锁。多进程部署会破坏此前提，故演进时必须先外置数据层。

## 6. 安全架构

| 威胁 | 防线 | 位置 |
|---|---|---|
| 密码泄露 | scrypt 加盐哈希（salt 16 字节随机）；响应永不携带 hash/salt（publicUser 白名单字段） | server.js:19-26 |
| 未授权访问 | 除 health/plans/login/静态页外全部要求 Bearer 令牌；单证页 query token 二次校验 | server.js:856-866, 717-721 |
| 越权操作 | requireBoss 服务端 403（删数据/动库存/员工/设置）；前端隐藏按钮仅是体验层 | server.js:182-184 |
| XSS | 前后端所有动态字符串经 esc() 转义后才进 innerHTML/HTML 模板 | app.js:17, server.js:17 |
| 路径穿越 | 静态页白名单枚举；照片文件名 `^[A-Za-z0-9._-]+$` + 解析后前缀校验 | server.js:839-855 |
| 伪造图片 | 扩展名声明 + 魔数双校验（FFD8/8950/RIFF-WEBP） | server.js:460-463 |
| 超大请求 | readBody 8MB 上限即断流 | server.js:814-830 |
| 会话劫持/离职风险 | 重置他人密码、删除员工即清除其全部会话 | server.js:682, 694 |
| 自我锁死 | 不能删除自己、不能降级自己 | server.js:675, 690 |
| 金额篡改 | 订单 total/paid 服务端计算；改价仅允许 >0；收款禁超收；库存禁直改 | server.js:311, 336, 558-561, 414-416 |

## 7. 部署架构

```
./start.sh ──探测 Node──► exec node server.js ──► :8095
   探测顺序：PATH → /opt/homebrew → /usr/local
             → Doubao sandbox runtime → nvm/volta/fnm
```

| 项 | 值 |
|---|---|
| 运行时 | Node.js 18+（验证于 v22.23.2） |
| 端口 | `PORT` 环境变量，默认 **8095** |
| 数据目录 | `YW_DATA_DIR` 环境变量，默认 `./data`（测试隔离用） |
| 进程模型 | 单进程前台运行（start.sh exec）；停止 = Ctrl-C / kill，数据保留 |
| 静态资源 | 与 API 同进程同端口，无 nginx 依赖 |

**四系统同机共存**：

| 系统 | 端口 | 技术栈 |
|---|---|---|
| ride-pro | 8090/2182/8093/2090x/9101 | Java Dubbo 多进程 |
| payment-pro | 8080/8443/2181/8092/2088x | Java Dubbo 多进程 |
| **yiwu-pro** | **8095** | **Node 单进程** |
| cs-pro | 8096 | Java Spring Boot 单进程 |

**测试隔离**：`YW_DATA_DIR=/tmp/yw-test PORT=8097 node server.js` 起独立实例跑 verify.mjs，不污染演示库（8096 已被 cs-pro 占用，故隔离实例用 8097）。

## 8. 关键设计决策（ADR 摘要）

| # | 决策 | 备选 | 理由 | 代价与升级路径 |
|---|---|---|---|---|
| ADR-1 | 拍照识货 = 浏览器 dHash + 服务端汉氏距离 | 视觉大模型 API | 零依赖、离线、无费用；64 位指纹比对 O(n) 足够 | 只能「同款/相近角度」匹配，非语义识别；recognize 端点可整体替换为视觉 API |
| ADR-2 | 1688 导入 = CSV 文件/粘贴 | 开放平台 API 直连 | API 需企业凭证，原型不可得；卖家后台导出是现成通路 | 手工导出一步；凭证到位后加 API 拉单，导入管线复用 |
| ADR-3 | 库存允许负数 | 缺货禁售 | 档口现实：缺货也先接单后补货 | 负数标红预警不阻塞成交 |
| ADR-4 | 单证 = 服务端 HTML 打印页 | PDF 生成库 | 零依赖；浏览器「另存 PDF」即正式单证 | 样式受浏览器打印影响；打印 CSS 已固定 A4 版式 |
| ADR-5 | 存储 = 单 JSON + 原子写 | SQLite/PG | 零依赖；档口数据量内存全量计算无压力 | 单写者；规模化先迁数据层 |
| ADR-6 | 前端全量状态刷新 | 增量推送/WebSocket | 简单可靠无缓存一致性问题 | 数据量大后流量上升；演进加分页/增量 |
| ADR-7 | 应收实时计算不落库 | 快照表+调度 | 永远一致、无调度器 | 订单量极大时 O(n) 变慢；届时加索引/快照 |
| ADR-8 | 会话存内存 | 持久化会话 | 零依赖 | 重启需重登（7 天 TTL 内）；演进落盘 |
| ADR-9 | 订单/客户名快照 | 纯引用 | 历史订单不受改价改名影响；客户改名显式同步显示名 | 快照与档案可能不一致（设计意图） |

## 9. 可靠性与一致性机制（服务端兜底清单）

1. 收款：>0 且 ≤ 未收余额；报价单拒收；paid 服务端累加（server.js:555-570）。
2. 状态机：TRANSITIONS 白名单，非法跳转 409；shipped/cancelled 终态（server.js:303-308, 532-553）。
3. 库存：唯一入口 adjustStock，直改 stock 被拒；确认扣/取消补自动联动（server.js:219-238, 414-416）。
4. 应收：仅 confirmed/shipped 未结清计入；账龄自确认日；分币种不混加（server.js:186-217）。
5. 金额：round2 统一两位小数；数量正整数上限 1e7；金额上限 1e9（server.js:14, 163-164）。
6. 幂等：1688 导入按 externalNo 去重，重复提交跳过（server.js:593, 599-603）。
7. 快照：订单创建时固化 sku/name/unit/price（server.js:339）。
8. 持久化：tmp→rename 原子落盘（server.js:132-137）。
9. 删除保护：有订单客户禁删 409；不能删/降级自己（server.js:515, 675, 690）。

## 10. 演进路线

| 阶段 | 触发条件 | 改造点 |
|---|---|---|
| 数据层外置 | SKU/订单量超出内存全量刷新舒适区 | SQLite/PG + 分页接口；业务规则层不动 |
| 会话持久化 | 重启频繁影响体验 | 会话落盘或签名令牌 |
| 识货升级 | 需要语义识别（「找类似的红色款」） | recognize 替换为视觉大模型 API（Key 放仓库外 ~/.config/） |
| 1688 直连 | 取得开放平台企业凭证 | API 拉单 → 复用现有导入管线 |
| 提醒推送 | 催款自动化需求 | 定时任务 + 微信/WhatsApp 通知 |
| 商业化 | 正式售卖 | 定价页接支付与订阅计费；按套餐做功能开关 |
| 多实例 | 多档口连锁 | 数据层外置完成后，反向代理 + 多进程 |
