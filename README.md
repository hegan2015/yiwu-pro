## 1. 产品定位

面向义乌市场档口小老板的轻量经营系统：**内贸批发 + 小额外贸混做**，替代「微信聊天 + Excel 记账」。

典型用户画像：市场档口 + 外贸/批发混合、SKU 极多、靠微信/WhatsApp 接单、赊账普遍、人手少、预算敏感。

### 1.1 市场缝隙（调研结论）

| 需求 | 秦丝类进销存 | OKKI 类外贸 SaaS | Chinagoods 官方平台 |
|---|---|---|---|
| 手机快速开单 | ✅ | 部分 | ❌ |
| 应收账龄 + 催款 | 弱 | ✅ | ❌ |
| 美元报价 + 装箱单/发票 | ❌ | ✅ | 部分 |
| 1688 订单归拢 | 弱 | ❌ | ❌ |
| 档口可承受的价格 | ✅（免费~800/年） | ❌（19800/年起） | 会员费 |

**「内贸 + 小额外贸混做、几百元级定价、应收催款为核心」的组合目前没有现成产品完整覆盖**，这是本产品的切入点。

### 1.2 设计原则

1. **做轻做快**：核心动作（开单、收款、催款）三步内完成，让用户愿意放弃 Excel + 微信的惯性。
2. **可靠性放服务端**：金额口径、状态流转、权限、库存一致性全部由服务端校验兜底，前端只管展示。
3. **零依赖**：仅用 Node.js 内置模块，无 npm 安装、无外部服务，一条命令启动。

## 2. 功能清单

| 模块 | 功能点 |
|---|---|
| 开单 | 选客户自动带出币种（批发 ¥ / 外贸 $，可切换）；商品搜索；数量步进；**手动改价**（讲价场景）；存为报价单 / 直接确认 |
| 订单 | 状态流转 报价→已确认→已发货（可取消）；发货登记货代/目的地；收款记录（多笔、多方式）；报价单一键复制（中文发微信 / 英文发 WhatsApp）；1688 来源标记 |
| 应收对账 | 分币种总额 + 账龄分层（0-30 / 31-60 / **60+ 高危**）；按客户汇总欠款、逐单拖款天数；催款单一键复制（中/英）；快捷收款 |
| 拍照识货 | 商品照片档案；拍照/选图 → 浏览器端感知哈希 → 服务端相似度比对 → 一键加入订单 |
| 精确库存 | 出入库流水（每笔含前后值/原因/操作人）；采购入库；盘点差异调整；订单确认自动扣减、取消自动回补；缺货预警（阈值可配）；允许负库存（档口缺货也接单的现实） |
| 外贸单证 | 商业发票 / 装箱单（中英双语 HTML 打印页，浏览器另存 PDF）；箱规自动算箱数/体积 CBM/毛净重；公司抬头/银行信息/贸易条款可配；缺箱规显式警告 |
| 1688 导入 | CSV 文件导入（自动识别 UTF-8/GBK）或粘贴；列名模糊映射；预览确认；同单多行合并；**订单号去重**（重复导入幂等）；自动创建客户/商品；已付款订单自动记收款、未付款转报价 |
| 多用户权限 | 老板/店员两角色；scrypt 加盐哈希密码；会话令牌（7 天）；员工增删、重置密码、角色调整 |
| 商品/客户 | 商品：货号唯一、双币价格、单位、HS 编码、箱规、照片；客户：类型/联系人/备注、列表直显欠款；有订单客户禁删 |
| SaaS 定价 | 公开定价页 `/pricing.html`：三档套餐按功能模块定价，月付/年付切换（年付省 2 个月），功能对比表 |

## 3. 技术架构

```
浏览器（手机优先 SPA）                 Node.js 单进程服务（:8095）
┌─────────────────────────┐           ┌──────────────────────────────┐
│ index.html + app.js     │  HTTP/JSON │ server.js（node:http）        │
│  · 五页签：开单/订单/    │ ─────────► │  · 路由 + 会话鉴权中间件      │
│    应收/货品/更多        │  Bearer    │  · 业务校验（金额/流转/权限） │
│  · canvas 感知哈希计算   │  Token     │  · 应收/库存口径统一计算      │
│  · CSV 解析（GBK 兼容）  │            │  · 单证 HTML 渲染             │
│ pricing.html（公开）     │            │  · JSON 原子持久化            │
└─────────────────────────┘           └──────────────┬───────────────┘
                                                     │
                                      data/store.json（先写 .tmp 再 rename）
                                      data/photos/<productId>.<ext>
```

- **运行时**：Node.js 18+（验证于 v22）。本机 PATH 无 node 时 `start.sh` 自动探测常见安装位置。
- **存储**：单 JSON 文件 + 原子写入（write tmp → rename），重启不丢数据；照片独立目录存储。
- **鉴权**：`crypto.scryptSync` 加盐哈希；`crypto.randomBytes` 会话令牌，内存 Map 管理，7 天过期；API 走 `Authorization: Bearer`，单证页走 `?token=`（新标签页场景）。
- **前端**：原生 JS 单页应用，无框架无构建；所有动态内容经 HTML 转义后渲染（防 XSS）；底部五页签导航，移动端优先、桌面居中 760px。

## 7. 服务端兜底规则（一致性保证）

1. **收款**：金额 > 0 且 ≤ 未收余额（超收拒绝）；报价单未确认不能收款；`paid` 由服务端累加。
2. **状态机**：`quote → confirmed/cancelled`，`confirmed → shipped/cancelled`，`shipped/cancelled` 终态；非法跳转 409。
3. **库存**：只能通过流水变动（入库/盘点/订单确认扣减/取消回补），PUT 商品直接改 stock 被拒；每笔流水记录 before/after/原因/操作人，可审计。
4. **应收口径**：仅 confirmed/shipped 且未结清订单计入；账龄自确认日起算；分币种汇总（CNY/USD 不混加）；全部服务端计算，前端只展示。
5. **金额**：两位小数.round2 统一处理；价格/数量边界校验（正整数数量、正价格、上限）。
6. **幂等**：1688 导入按 externalNo 去重，重复提交跳过；同单多行合并为一单。
7. **快照**：订单创建时快照商品名/货号/单价，后续改价不影响历史订单；客户改名同步订单显示名。
8. **安全**：密码 scrypt 加盐哈希、响应永不携带 hash/salt；照片魔数校验拒伪造；图片文件名白名单防路径穿越；前端全量 HTML 转义防 XSS；重置密码即踢掉该用户其他会话。
9. **持久化**：先写 `.tmp` 再 `rename` 原子落盘，进程崩溃不损坏数据文件。

## 8. 关键设计决策

### 8.1 拍照识货 = 本地感知哈希（不依赖外部 AI）
- 浏览器 canvas 将图片缩至 9×8 灰度，相邻像素比较生成 64 位 dHash（16 位 hex）。
- 服务端对商品照片指纹做汉氏距离排序：≤6 很可能同款，≤10 相似，其余仅供参考。
- 零依赖、离线可用、无 API 费用；局限是「同款/相近角度」匹配而非语义识别。升级路径：接入视觉大模型 API（配置 key 即可替换 recognize 实现）。

### 8.2 1688 导入 = CSV 文件而非开放平台 API
- 1688 开放平台 API 需企业应用凭证，原型阶段不可得；卖家后台订单导出 CSV 是现成通路。
- 浏览器端 `TextDecoder('utf-8', {fatal})` 失败自动回退 GBK（1688 导出常见编码）。
- 列名模糊匹配（订单编号/买家/货品名称/数量/单价…），缺必需列明确报错。

### 8.3 库存允许负数
- 档口现实：缺货也先接单后补货。确认订单照扣库存，负数标红「缺货」预警，不阻塞成交。

### 8.4 单证 = 服务端渲染打印页
- 不引 PDF 库：HTML + 打印 CSS，浏览器「打印/另存 PDF」即得正式单证。
- 箱数 = ⌈数量/每箱装量⌉，体积 = 长×宽×高/10⁶×箱数，毛净重 = 单箱重×箱数；缺箱规行显示「—」并顶部警告。

## 10. 快速开始

```bash
cd yiwu-pro
./start.sh          # 自动探测 Node 运行时，启动于 http://localhost:8095
```

- 演示账号：`boss / boss123`（老板）、`clerk / clerk123`（店员）
- 首次启动自动注入种子数据：8 种小商品、4 个客户（2 批发 2 外贸）、4 笔订单（覆盖 70 天老账、部分收款、新报价）
